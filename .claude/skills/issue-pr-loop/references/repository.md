# ModularPipelines

Read [AGENTS.md](../../../../AGENTS.md) for guarded build/test commands, formatting, documentation builds, and generated-option constraints.

- Run local .NET commands through `scripts/Invoke-AgentDotNet.ps1` using in-process PowerShell array binding. Respect its time/memory limits; never build/format the all-project solution or execute the build pipeline without explicit authorization.
- Change generators/scrapers and regenerate options; do not hand-edit generated output or preserve obsolete generated APIs with shims.
- For a generator or scraper fix, open the PR with the generator change and its tests as soon as they pass locally. Do not hold the PR until hosted regeneration finishes: dispatch the [Generate CLI Options workflow](../../../../.github/workflows/generate-cli-options.yml) when the change needs fresh output, name the run in the PR body, and report `opened #N closing #M`. When an issue can only move after a dispatched run, report `waiting #N: run <id>` instead of adding `on-hold`.
- Generated output ships through the automated `[Automated] Update <tool> CLI Options` PRs, not through issue PRs or issue chains. A generator or scraper issue is delivered when its generator PR merges: after the merge, dispatch generation for the affected tools with `create-pr=true`, link the run on the issue, and close the issue when its remaining acceptance criteria concern only the regenerated output. Do not file "regenerate and validate" sub-issues, and do not carry generated files in an issue PR to beat the freshness check: every generator merge makes such snapshots stale. Close existing issues of that kind as superseded by the automated PR or the dispatched run.
- Follow [pull request maintenance](../../../../AGENTS.md#pull-request-maintenance) for autogenerated CLI options PRs, closed-PR CI cancellation, and review-thread resolution.
- Stop only services created for the current worktree; shared lock Redis must remain running.
