Install packages

Usage: pnpm install [OPTIONS]

Options:
  -P, --prod
          Install only production dependencies. devDependencies are skipped, and removed if already installed
          
          [alias: --production]

  -D, --dev
          Install only devDependencies. Regular dependencies are skipped, and removed if already installed

      --optional
          Include optionalDependencies even when the configured default excludes them

      --no-optional
          Don't install optionalDependencies

      --cpu <CPU>...
          CPU architectures whose platform-specific optional dependencies should be installed. Repeat or comma-separate for multiple values

      --os <OS>...
          Operating systems whose platform-specific optional dependencies should be installed. Repeat or comma-separate for multiple values

      --libc <LIBC>...
          libc families whose platform-specific optional dependencies should be installed (`glibc`, `musl`). Repeat or comma-separate for multiple values

      --frozen-lockfile
          Don't generate a lockfile, and fail if an update to it is needed. This setting is enabled by default in CI when a lockfile is present

      --no-frozen-lockfile
          Allow the lockfile to be updated, overriding a `frozenLockfile: true` setting

      --lockfile-only
          Only update `pnpm-lock.yaml`. Don't download packages or write `node_modules`

      --fix-lockfile
          Repair broken lockfile entries by re-resolving their metadata while preserving compatible locked versions

      --lockfile-dir <dir>
          The directory in which `pnpm-lock.yaml` is created. Several projects may share a single lockfile

      --merge-git-branch-lockfiles
          Fold every per-branch lockfile (`pnpm-lock.<branch>.yaml`, written under the `gitBranchLockfile` setting) into `pnpm-lock.yaml` and delete them

      --merge-git-branch-lockfiles-branch-pattern <MERGE_GIT_BRANCH_LOCKFILES_BRANCH_PATTERN>
          Glob patterns naming the branches that merge the per-branch lockfiles, so a mainline branch does not have to pass `--merge-git-branch-lockfiles` by hand

      --dry-run
          Show what an install would change without writing anything to disk

      --force
          Reinstall every package the lockfile names: relink packages an earlier install already materialized, and install optional dependencies whose `cpu` / `os` / `libc` / `engines` don't match the host instead of skipping them

      --prefer-frozen-lockfile
          Prefer the existing lockfile over re-resolving, even when the manifest may have changed

      --no-prefer-frozen-lockfile
          Always re-resolve against the registry instead of preferring the existing lockfile

      --ignore-manifest-check
          Skip the check that `pnpm-lock.yaml` is up to date with `package.json` under `--frozen-lockfile`. For callers that just wrote the lockfile themselves and know the manifest is about to catch up

      --no-runtime
          Don't install runtime dependencies (`node`, `deno`, `bun`). Their archives aren't fetched and their bins aren't linked; the rest of the install proceeds normally

      --ignore-scripts
          Don't run lifecycle scripts of the project or its dependencies. Packages are still installed; only their build scripts are skipped, and the install won't fail because of it

      --no-ignore-scripts
          Run lifecycle scripts even when the configuration disables them

      --ignore-pnpmfile
          Disable pnpm hooks defined in `.pnpmfile.cjs`, including the pnpmfiles of config dependencies

      --node-linker <NODE_LINKER>
          Which node linker to use: `isolated` (the default, a symlinked store), `hoisted` (a flat `node_modules`), or `pnp` (Plug'n'Play). Overrides the configured value
          
          [possible values: isolated, hoisted, pnp]

      --offline
          Fail on a cache miss instead of fetching from the registry, using only packages already in the store

      --no-offline
          Allow network fetches even when the configuration enables offline mode

      --frozen-store
          Open the store read-only and skip all store writes. For installing against a store on a read-only filesystem (e.g. a Nix store); pair with `--offline --frozen-lockfile`

      --no-frozen-store
          Allow store writes even when the configuration enables the read-only store

      --prefer-offline
          Prefer packages already in the cache over the network, even past their freshness window

      --no-prefer-offline
          Don't prefer cached packages even when the configuration enables it

      --trust-lockfile
          Skip verifying the lockfile against supply-chain policies

      --no-trust-lockfile
          Verify the lockfile against supply-chain policies even when the configuration trusts it

      --update-checksums
          Refresh the integrity checksums in `pnpm-lock.yaml` from the registry. Cannot be combined with `--frozen-lockfile`

      --network-concurrency <NETWORK_CONCURRENCY>
          Maximum number of concurrent network requests during install

      --fetch-timeout <FETCH_TIMEOUT>
          Per-request network timeout, in milliseconds

      --fetch-warn-timeout-ms <FETCH_WARN_TIMEOUT_MS>
          Warn when a registry metadata request takes longer than this many milliseconds

      --fetch-min-speed-ki-bps <FETCH_MIN_SPEED_KI_BPS>
          Warn when a tarball download's average speed is below this many KiB/s

      --user-agent <USER_AGENT>
          `User-Agent` header to send on registry requests

      --pnpr-server <PNPR_SERVER>
          URL of a pnpr server to offload resolution and file fetching to. `node_modules` is still linked locally from the server-produced lockfile

      --color[=<COLOR>]
          Force colored output

  -y, --yes
          Automatically answer yes to prompts

  -C, --dir <DIR>
          Set working directory. Accepted anywhere on the command line, before or after the subcommand, like every other rc-option
          
          [default: .]

      --store-dir <DIR>
          Directory in which the package store is created. Relative paths are resolved from the workspace root, or from `--dir` outside a workspace

      --state-dir <DIR>
          Directory in which pnpm persists machine-local state

      --npmrc-auth-file <NPMRC_AUTH_FILE>
          Path to an `.npmrc` to read auth settings from, overriding the default `~/.npmrc`
          
          [alias: --userconfig]

      --registry <REGISTRY>
          Base URL of the npm registry to resolve and fetch packages from. Universal rc-option: accepted on every command and layered onto the config like `--config.registry=<url>`. Commands that expose their own `--registry` still read the same value

      --https-proxy <HTTPS_PROXY>
          Proxy for HTTPS registry and tarball requests

      --http-proxy <HTTP_PROXY>
          Proxy for HTTP registry and tarball requests

      --no-proxy <NO_PROXY>
          Hosts that bypass configured proxies

  -r, --recursive
          Run the command for every project in the workspace instead of only the project in `--dir`

      --reporter <REPORTER>
          Reporter output format

          Possible values:
          - default:     Rich visual output: a progress line, a packages diff, lifecycle output, and a `Done in ...` summary. The default; renders in place on a terminal and falls back to `append-only` output when stdout is not a terminal
          - append-only: Like `default` but forces the append-only rendering even on a TTY — one line per update, no cursor movement
          - ndjson:      Newline-delimited JSON on stderr
          - silent:      No progress output
          
          [default: default]

      --loglevel <LOGLEVEL>
          What level of logs to print. Mirrors pnpm's universal `--loglevel` option: `silent` selects the silent reporter over any `--reporter` choice; the other levels cap the default reporter's output
          
          [possible values: silent, error, warn, info, debug]

  -F, --filter <FILTER>
          Select which workspace projects to run on. Repeat to add more. Each selector can be a name pattern (`@scope/*`), a path (`./pkg`), a dependency query (`foo...`), an exclusion (`!bar`), a directory (`{dir}`), or a changed-since query (`[since]`)

      --filter-prod <FILTER_PROD>
          Like `--filter`, but follow only production dependencies when selecting projects

  -w, --workspace-root
          Run the command on the root workspace project

      --fail-if-no-match
          Exit with code 1 when the `--filter` / `--filter-prod` selectors match no workspace project

      --include-workspace-root
          Also run a recursive command on the root workspace project, which `run` / `exec` / `add` / `test` otherwise leave out

      --no-include-workspace-root
          Leave the root workspace project out of a recursive command, overriding an `includeWorkspaceRoot: true` setting

      --test-pattern <TEST_PATTERN>
          Glob patterns naming test files, used by the `[since]` `--filter` selector to decide which changes count

      --changed-files-ignore-pattern <CHANGED_FILES_IGNORE_PATTERN>
          Glob patterns of changed files that the `[since]` `--filter` selector should ignore

      --sort
          Keep recursive workspace projects sorted topologically

      --no-sort
          Run recursive workspace projects in workspace order

      --reverse
          Process recursive workspace projects in reverse order

      --workspace-concurrency <WORKSPACE_CONCURRENCY>
          Maximum number of workspace projects to process in parallel

      --parallel
          Run scripts in every selected workspace project concurrently, disregarding topological sorting

      --stream
          Stream a recursive command's script output as it arrives, one prefixed line at a time

      --aggregate-output
          Hold each script's streamed output until the script exits, then print it as one block

      --use-stderr
          Divert the reporter's output to stderr, leaving stdout for the command's own result

      --ignore-workspace
          Run as if the project were standalone, ignoring any `pnpm-workspace.yaml` above it

      --workspace-packages <WORKSPACE_PACKAGES>
          Glob patterns selecting the workspace's projects, overriding the `packages` field of `pnpm-workspace.yaml`. Repeat to add more

  -h, --help
          Print help (see a summary with '-h')
