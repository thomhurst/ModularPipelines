# Repository guidance

ModularPipelines is a C# pipeline framework with dependency-driven, parallel modules.

## Build and test

- Use the SDK pinned in `global.json`.
- Run every local `dotnet` command through `scripts/Invoke-AgentDotNet.ps1`, in-process as below. From another shell, use `pwsh -Command "& scripts/Invoke-AgentDotNet.ps1 ..."`; `pwsh scripts/Invoke-AgentDotNet.ps1 ...` loses array binding.
- The guard defaults to 10 minutes and 2 GB, disables reusable build servers, and cleans up the process tree. Allow any outer execution timeout at least 30 seconds beyond `-TimeoutSeconds`. Exit `124` means timeout; `137` means memory limit. Report the validation limit and defer the expensive check to CI; do not automatically raise limits and retry.
- Build the affected solution: `ModularPipelines.slnx` for core, `ModularPipelines.Tests.slnf` for core plus tests, or `src/ModularPipelines.<Tool>/ModularPipelines.<Tool>.slnx` for one integration (including its tests when present). Analyzer and example solutions are available for those areas.
- Do not build or format `ModularPipelines.All.slnx`, or execute `src/ModularPipelines.Build`: these can exhaust workstation resources. A full build requires an explicit human request and sufficient capacity. Validate build-pipeline changes by building only its project.
- Run the relevant TUnit executable test project. For focused runs, append `--treenode-filter` and one pattern after `--`; combine patterns only with valid TUnit OR parentheses.
- Keep integration tests in their matching `ModularPipelines.<Tool>.UnitTests` project; do not add integration references to the core unit tests.

```powershell
& scripts/Invoke-AgentDotNet.ps1 -SingleNode `
  -DotNetArguments @('build', 'ModularPipelines.slnx', '-c', 'Release')

& scripts/Invoke-AgentDotNet.ps1 `
  -DotNetArguments @('run', '--project', 'test/ModularPipelines.UnitTests/ModularPipelines.UnitTests.csproj', '--framework', 'net10.0', '--', '--coverage', '--coverage-output-format', 'cobertura')

# Format the affected solution before committing code changes.
& scripts/Invoke-AgentDotNet.ps1 `
  -DotNetArguments @('format', 'ModularPipelines.slnx')
```

CI checks formatting with `format <solution> --verify-no-changes --severity info`.
For documentation changes, use the Node version range in `docs/package.json` and run
`yarn install` and `yarn build` from `docs/`.

## Code constraints

- Tool options are generated by `tools/ModularPipelines.OptionsGenerator/`. Fix the scraper or generator, preferably its generic logic, and regenerate; never hand-edit generated options, including during review or simplification.
- Current tool output is authoritative, even when regeneration breaks an earlier API. Do not preserve generated APIs with handwritten shims, aliases, obsolete forwarding members, or manual extension files.
- Library code under `src/` uses `ConfigureAwait(false)`; tests need not.

Keep agent guidance focused on non-obvious repository constraints. Link to existing
configuration or scripts instead of duplicating their contents.
